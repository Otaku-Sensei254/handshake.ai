# Migration: Supabase → Neon

## Summary

Migrate the database from Supabase (IPv6-only free tier) to Neon (free tier, IPv4-native). Neon supports pgvector and pgcrypto, so no schema changes are needed beyond adding extension declarations.

## What stays the same

- All SQL queries — `postgres` library works identically
- pgvector operations — `<=>` cosine similarity, `vector` type columns
- UUID generation — `gen_random_uuid()` works via pgcrypto
- Schema — all tables, columns, indexes remain identical
- Code structure — same files, same functions

## What changes

1. Connection string — swap Supabase hostname for Neon hostname
2. Remove all IPv6 socket factory workaround code (dns/net imports)
3. Add `CREATE EXTENSION IF NOT EXISTS` for vector and pgcrypto in migration

## Prerequisites

1. Create a Neon project at https://neon.tech (free tier)
2. Get the connection string from Neon dashboard (format: `postgresql://user:pass@hostname:5432/dbname`)
3. Note: Neon connection strings include `?sslmode=require` by default

## Steps

### 1. Update `.env` (root)

Replace:
```
DATABASE_URL=postgresql://postgres:Handshake%40ai2026@db.tmcsffludppvngdzmmlj.supabase.co:5432/postgres
```
With Neon connection string:
```
DATABASE_URL=postgresql://<user>:<password>@<hostname>.neon.tech:5432/<database>?sslmode=require
```

### 2. Update `web/.env.local`

Same replacement for `DATABASE_URL`.

### 3. Update `src/db/supabase.ts`

Remove the `dns` and `net` imports and the `socket` factory. Restore simple `postgres(DATABASE_URL, { max: 10 })`.

### 4. Update `web/lib/db.ts`

Remove the `dns` and `net` imports and the `socket` factory. Restore simple `postgres(process.env.DATABASE_URL!, { ssl: isProd ? 'require' : false, max: 10 })`.

### 5. Update web API routes (6 files)

Remove the `dns`/`net` imports and `socket` factory from:
- `web/app/api/users/route.ts`
- `web/app/api/register/route.ts`
- `web/app/api/seed-demo/route.ts`
- `web/app/api/organizer/events/[id]/insights/route.ts`
- `web/app/api/bot/route.ts` (2 instantiations)

Restore simple `postgres(process.env.DATABASE_URL!, { ssl: isProd ? 'require' : false, max: 5 })`.

### 6. Update `src/db/migrate.ts`

Add extension declarations at the start:
```ts
await sql`CREATE EXTENSION IF NOT EXISTS vector`;
await sql`CREATE EXTENSION IF NOT EXISTS pgcrypto`;
```

### 7. Run migration

```bash
npx ts-node src/db/migrate.ts
```

### 8. Restart both dev servers

```bash
# Terminal 1
npm run dev

# Terminal 2
cd web && npm run dev
```

## Risk

- **Low** — Neon is PostgreSQL-compatible, pgvector is supported, pgcrypto is supported
- Connection string format is standard — the `postgres` library works with it unchanged
- No data migration needed since we're creating a fresh database

## Validation

1. `npm run dev` in root → bot starts without `CONNECT_TIMEOUT` or `ENETUNREACH`
2. `npm run dev` in `web/` → web app starts, `/api/users` returns data
3. Matching cycle completes successfully (no `Socket is closed` errors)
4. `/api/consent` and `/api/negotiate` respond within seconds
